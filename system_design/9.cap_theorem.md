# CAP Theorem

CAP theorem states that it is impossible for a distributed system to simutaneously provide all 3 of following desirable properties:

## Concistency (C) - All nodes same data at the same time. It is equivalent to having a single up-to date copy of the data

## Avilability (A) - Every request received by a non-failing node in the system must result un a response. Refers to a system's ability to remain accessibe even if one or more nodes in the system go down

## Patrition tolerance (P) - Partition is a communication break (or a network failure) between ano two nodes in the system when both nodes are up but cannot communicate with each other. A partition-tolerant system continues to operate even if there are partitions in the system. Data is sufficiently replicated across combinations of nodes and networks to keep the system up through intermirrent outages (периодические сбои)

According to the CAP theorem, any distributed system needs to pick two out of three properties. CA/CP/AP.

Howewer, CA is not really coherent option, as a system that is not partition-tolerant will be forced to give up either Consistency or Availability in case of network partition.

### In the presence of a network partition, a distributed system must shoose either Consistency or Avilability.

To be consistent, all nodes should see the same sets of updates in the same order. But if the network loses a partition, updates in one partition might not make it to the other partitions before a client reads from the out-of-date partition after having read from the up-to-date one. (Если произойдет сбой(partition), то обновления, записанные в одной части системы, могут не дойти до другой части вовремя. Из-за этого клиент может сначала увидеть новые данные, а потом - старые, если обратится к узлу, который еще не получил последние изменения)

The only thing that can be done to cope with this possibility is to stop serving requests from the out-of-date partition, but then the service is no longer 100% available.
