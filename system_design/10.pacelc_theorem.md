# PACELC Theorem

One place where CAP theorem is silent is what happens when there is no network partition?

## Solution

The PACELC theorem statas that in a system that replicates data:

- if there iss a partition ('P'), a distributed system can tradeoff between availability (A) and consistency (C) - CAP theorem

- else 'E', when the system is running normally in the absence of partitions, the system can tradeoff between latency ('L') and consistency ('C')

## Examples

- Dynamo and Cassandra are PA/EL systems: They choose availability over consistency when partition occurs; otherwise they choose lower latency

- BigTable and HBase are PC/EC systems: They will always choose consistency, giving up availability and lower latency.

- Mongo DB can be considered PA/EC (default configuration):
    - All writes and reads are performed on primary. As all replication is done async (from primary to secondaries), when there is a network partition in which primary is lost or becomes isolated on the minority side, there is a chance of losing data that is unreplicated to secondaries, so, there is a loss of consistency during partitions. Conclusion: In the case of network partition, MongoDB chooses availability, but otherwise guarentees consistency.

    - When MongoDB is configured to write on pajority replicas and read from the primary, it could be categorized as PC/EC (concistency oriented)
