# Key Characteristics of Distributed Systems

> Scalability, Reliability, Availability, Efficiency and Manageability


## Scalability

Capability of the system to grow and manage increased demand.
System may have to scale because: increased emount of data, or number of transactions etc.

### Horizontal vs Vertical Scaling:
- horizontal - add more servers (good example Cassandra and Mongo DB)
- vertical - add more cpu/ram/storage to existing (!) servers (good example MySQL)

## Reliability

Ability of a system to operate correctly and effectively in the presence of errors/failures.
If one component of the system is down and the system is delivering it's services - good reliability

Good example - electronic commerce store (like Amazon). If a user has added an item to their shopping cart, the system is expected not to loose it. A reliable system achieves this through redundancy of both software components and data. If the server carrying the user's shopping cart fails -> another server that has the exact replica of the shopping cart should replace it.

(!) Redudancy has costs.


Fault Tolerance - abvility system to continue operating (possibly at reduced level) even if one of it's components fail.

## Difference Between Reliability and Fault Tolerance

Reliability - end to end correctness and consistency over the time
Fault tolerance - ability to continue operating when individual components fail

Reliability - user-centric concept. Can the system consistently meet user's expectations over the time?
Fault tolerance - system-centric concept. How does the system handle internal failures or component breakdowns?

Reliability measured as updime, error rates, mean time between failures (MTBF)
Fault tolerance - how quickly and effectively the system detects, isolates and recovers from failures.


## Availavility

Percentage of time that system is operational under normal conditions.

### Reliability vs Availability
If the system is reliable -> it's available.
Howewer (!) if it's available -> not always reliable.

It's possible to acheive high availability even with unreliable product by minimizing repair time and ensure that system is always available.

## Efficency
- response time (or latency)
- throughput (or bandwidth) - nb of items delivered in a given time unit (e.g. a second)

2 measures correspond to the following unit costs:
- nb of messages globally sent by the notes of the system (regardless of the size)
- size of messages representing the volume of data exchanges

Analysis of a distributed structure in terms of nb of messages is over-simplistic.

## Serviceabiliy or Manageability
- how easy it is to operate and maintain. (speed the system can be repaired or maintained)

If the time to fix increases -> availability decreases.

Early detection of faults can decrease or avoid system downtime.
