# Quorum

Quorum is the minimum number of servers on which a distributed operation needs to be performed successfully before declaring the operation's overall success.

Quorum enforces the consistency requirement needed for distributed operations.

### What value should we choose for a quorum?
1) More than half of the number of nodes in the cluster: (N/2 + 1) where N is the total number of nodes in the cluster.
It is recommended to always have an odd number of total nodes in the cluster.

2) Quorum is achieved when nodes follow the below protocol: R + W > N, where:
- N = total nodes in the cluster
- W = minimum nb successfull response from any types of nodes to confirm write operation
- R = minimum nb successfull response from any types of nodes to confirm read operation

Two things should be kept in mind before decided read/write quorum
- R = 1 and W = N -> full replication (write-all, read - one): undesirable when servers can be unavailable because writes are not guaranteed to complete.
- Best performance (throughput/availability) when 1 < R < W < N, because reads are more frequent than writes in most applications

## How It Works

- Bajority-Based Quorum: The most common type of quorum where an operation requires a majority (more thant half) of the nodes to agree to participate. E.g. in a system with 5 nodes, at least 3 must agree for a decision to be made.
- Read and Write Quorums: For read and write operations, differtent quorum sizes can be defined. Ex. system might require 4 nodes and a reqad quorum of 2 nodes in a 5-node cluster.

## Use Cases

### Distributed Databases
- Ensuring consistency in a database cluster, where multiple nodes might hold copies of the same data.

### Cluster Management
- In server clusters, a quorum decides which nodes form the "active" cluster. Especialy important when a cluster might be divided into two parts, each believing it is the active cluster. (If the number of "alive neighbors" together with the node itself is ≥ quorum, it stays active. If it’s less, the node switches to passive mode (read-only or stopped))

### Consensus Protocols
- In algorithms like Paxor or Raft, a quorum is curcial for achieving consensus among distributed nodes regarding the state of the system or the outcome of an operation.

## Advantages
- Fault Tolerance: Allows the system tolerate a certain number of failures while still operating correctly
- Consistency: Helps maintain data consistency across distributed nodes.
- Availability: Increases the availability of the system by allowing operation to preoceed as logn as the quorum condition is met.

## Challenges
- Network Partitions: In cases of network failures, forming a quorum might be challenging, impacting system availability.
- Performance Overhead: Achieving a quorum, especially in large clusters, can introduce latency in decision-making processes.
- Complexity: Implementing and managing quorum based systems can be complex, particularly in dynamic environments with frequent node or network changes.

## Conclusion
Quorum is a fundamental concept in distributed systems, playing a crucial role in ensuring consistency, reliability and availability in envs where multiple nodes work together.

Whil it engances fault tolerance, it also introduces additional complexity and requires careful design and management to balance consistency, availability and performance.
