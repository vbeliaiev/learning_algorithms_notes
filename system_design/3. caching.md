# Caching

The cache is high-speed storage level. When the data is requested by the one application it is first checked in cache. If the data is found in cache -> it's returnded from cache. Otherwise it is retrieved from its original source.

## Key terninology and concepts

1) Cache - temp storage location for data or computation results, designed for fast access and retrivial.
2) Cache hit - when requested data is found in the cache
3) Cache miss - when a requested data item is not found in the cache
4) Cache eviction - the process of removing date from the cache, usually to clean space for the new data or predefined cache eviction policy.
5) Cache staleness - when the data in the cache is outdated compared to the original source

## Types of Caching

By physical storing methods:

1) In-memory caching - stores data in the main memory of computer. This is faster than access from disk storage. Usefull for frequently accessed data that can fit into available memory. Memcached or Redis libraries can used for this.

2) Disk caching - stores data on the hard disk. It's slower than memory cache but faster than retrieving data from a remote source. Is usefull for the data that is too large to fit in memory or data that needs to persist between application restarts. Commonly used for caching database queries and file system data.

By types and purposes:

3) Database caching - stores frequently accessed data in the database itself. Reduced the need to access external storage. This is useful for data that is stored in a database and frequently accessed by multiple users. Can be implemented using variety of techniques indcuding db query caching and result set caching.

4) Client side caching - occurs on the client side, such as web browser or app. To reduce request the data from the server. Example client-side caching - browser caching and local storage.

5) Server-side caching - occurs on the server, typically in web applications or other back-end services. Examples: full-page caching, fragment caching, object caching.

6) CDN caching - Сontent Delivery Network caching. Usefull for data that is acessed from multiple locations around the world. For static content.(images, videos, html/css/js etc)

7) DNS caching - type of cache used in the Domain Name System (DNS). Faster domain to IP resolution.
When a user requrests to access a website, their computer dends DNS query to the server to resolve website's IP. DNS server responds with the IP address and user's computer can then access the website using the IP address. This cache reduces nb of requests to DNS server.


## Cache Invalidation

1) Ensure Data Freshness
- when data changes (for ex product's price updates in the database) - you must remove or mark old (cached) data so, users don't see stale information.
- Without invalidation caches will keep serving outdated data

2) Maintain System Consistency
- large systems often have multiple caching layers. If any of these layers serve old data while others serve new data, users can encounter conflicting information.
-  properly invalidation caches helps maintain a consistent view of the system state

3) Balance Performance and Accuracy
- Cache invalidation strategies (e.g. time-to-live/TTL, manual triggers, event-based invalidations) are designed to minimize the performance cost of continously "refreshing" the cahce
- The goal is to keep data accurate to still benefit from the high-speed data retrieval.

4) Reduce Errors and Mismatched States
- When caches go stale -> risk presenting users wrong information or invalid results
- By strategically invalidation caches when data changes, you reduce bugs


### Cache invalidations schemes

1) Write-through cache
- write data into the cache and database in the same time
- allows fast retrieval, but we need to compleate data concistency between the cache and storage
- ensures nothing will get lost in a case of crash ...

2) Write-around cache
- data written directly to pemanent storage bypassing the cache
- disadvantage - read request for recetnly created data creates a "cache miss" and must be read from slower back-end storage and user will have higer latency

3) Write-back cache
- write to the cache alone and write to specific storage only after some time or conditions
- risk of data loss

### Cache Invalidation Methods
1) Purge
- removes cached content for specific object
- typically when there is an update of the content and the cached version is no longer valid.
- cached content is removed immediately, next request will be served from the origin server

2) Refresh
- fetches requested content from the origin server. When refresh request is received -> the cached content is updated the latest version from the origing server.
- refresh request doesn't remove the existing cached content. It updates instead.

3) Ban
- invalidates cached content based on specific criteria (url pattern, header etc). When a ban request is received any matched content is removed. Next query will be performed from the origin server.

4) Time-to-live (TTL) expiration
- set a TTL value for cached content. When content is stale (e.g. ttl value is expired) it must be refreshed.

5) Stale-while-revalidate
- when request is received -> cached version is immediately served to the user
- An asynchronous request is made to the origin server to fetch the latest version of the content.
- Once the latest version is available, the cached version is updated
- Used in web browsers and CDNs

## Cache read strategies

1) Read through cache
-  Caching mechanism is responsible for retroeving the data from data store when cache miss occurs.
-  Application trquests data from the data store directly.  If the requested data is not found (cache miss), the cache retrieves the data from cache store, updated the cache and returns the data to the application.

- Can improve performance when data retrieval is expensive and cache misses are relatively infrequent.

2) Read aside cache
- Application is responsible to read data from data store when a cache miss.
- Application checks the cache for the requested data. If cache is found (cache hit), the application uses this data.
- Howewer, if the data is missing, application retrieves the data from the store, updates the cache and then uses the data

- Provides better control over the caching process. App decide when and how to update the cache. Howewer it adds complexity in the code.
- Should use cache-aside when need caching and ensure that a failure of cache won't take down whole system. Application can always go to the DB if needed


## Cache eviction(удаление) policies

1) First In First Out (FIFO): Cache evicts the first block accessed first without any regard how often or how many times it was accessed before.
2) Last in First Out (LIFO): Cache evicts the most recrntly accessed block without any regard how often or how many times it was accessed before.
3) Least Recently Used (LRU): Discards the least recently used (not popular) items first.
4) Most Recently Used (MRU): Discards the most recently used items first.
5) Least Frequently Used (LFU): Counts how often an item is needed. Those that used least often are discarded first.
6) Random Replacement (RR): Randomly selects a candidate item and discards it to make space when necessary.
