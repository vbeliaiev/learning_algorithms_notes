# Load Balancing

Load Balancer (LB) - component of any distributed system. It helps to spread the traffic across a cluster of servers.

Load balancer could be at three_places:
- between user and the web server
- between web servers and an internal platform layer like application servers or cache servers
- between internal platform layer and database

[Client]───[LB]───┬───[Web Server]───┬───[LB]───┬───[App Server]───┬───[LB]───┬───[DB Server]
                  │                  │          │                  │          │
                  └───[Web Server]───┘          └───[App Server]───┘          └───[DB Server]

## Benefits of load balancing

- user experience faster. Requests are immediatelly passed on to a more readily available resource
- less downtime. If one server fails it redirects to another healthy one
- makes it easier for system administrators to handle incoming requests while decreasing wait time for users.
- smart LBs can make predictive analytics that handle traffic bottlenecks before they happen. Smart LBs can give an organisation raisonable insights. Key to automation.
- less failed or stressed components. (good for sys admins). Instead 1 device performs many work => many devices performs a little bit of work

## Load Balancing Algorithms

LBs concider 2 factors before forwarding a request to a backend server:
- server they choose responds
- use preconfigured algorithm to select one from the set of healthy servers

Health Checks - regular connections to the server to check if everything is ok.

### Load balancing methods:
- Least Connection Method - directs to the server with the fewest active connections
- Least Response Time Method - directs to the server with the fewest active connections and the lowest avg response time
- Least Bandwidth Method - directs to the server that s currently serving the least amount of traffic measured in Mbps
- Round Robin Method - cycles through a list of servers and sends request to the next server. It's most useful when the servers are of equal specification and there are not many persistent connections.
- Weighted Round Robin Method - Each server is assigned a weight. Servers with higher weight receives new connections before less weight servers. And high weight servers get more connections thatn less weights.
- IP Hash - a hash of IP address of client is calculated to redirect the request to a server.

## Redudant Load Balancers

The LB can be a single point of failure. To overcome this, a second load balancer can be connected to the first on the cluster. Each LB monitor the health of the other. And since they are all capable to serve the traffic and failure detection, even if the main LB is failure, the second load balancer will work.
